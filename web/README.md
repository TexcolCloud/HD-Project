# 寓见 Vue 管理端

正式宿管 Web 应用，使用 Vue 3、TypeScript、Vue Router 和 Vite。业务数据全部来自 Java `/api/v1`，不内置模拟业务数据。暖白与暖黑主题沿用已批准的界面基线。

## 启动

在本目录使用 Node.js 24.12 或以上版本：

```powershell
npm ci
npm run dev
```

打开 http://127.0.0.1:5173。Vite 将 `/api` 代理至 http://127.0.0.1:8080。启动后端后，使用宿管账号登录。本地种子账号说明见[共享接口契约](../contracts/API.md)。

如后端地址不同，启动前设置 `API_PROXY_TARGET`。浏览器请求保持同源路径，不将登录 Cookie 或 AI 密钥放入本地存储；本地存储只保留主题偏好。

## 检查与契约

```powershell
npm test
npm run build
npm run format:check
```

`npm run generate:api` 使用 `openapi-typescript` 从 `../contracts/openapi.json` 生成 `src/generated/api.ts`，构建时自动执行。实体和请求类型引用该文件，不手工维护另一套 DTO。依赖精确版本与 `package-lock.json` 一起锁定，TypeScript 采用与契约生成器兼容的 5.9.3。

API 传输层测试覆盖组合查询、Cookie 与 CSRF 写请求、幂等头，以及非 JSON 代理响应的可读错误。页面验证还需启动实际后端，完成登录、写入、图片与角色范围的浏览器联调。

查询使用 `useLatestQuery` 隔离列表与详情请求，过期响应无法覆盖当前选择。房间、楼栋编辑和房间详情位于 `src/components/housing/`。执行 `npm run format` 可按锁定的 Prettier 版本格式化源码。当前 API 1.3.0 的 Web 回归为 30 个文件、73 项测试，浏览器实测与导航见[最新界面与交付依据](../docs/18-界面收敛与交付版本.md)。此前的业务联合验收和结构治理分别见[16](../docs/16-服务闭环与联合验收.md)和[15](../docs/15-结构治理与联合回归.md)。

## 已实现

- 侧栏共四组八项。日常值班含工作台、访客登记，住宿档案含宿舍档案、学生入住，维修与调度含报修工单、任务调度，卫生与统计含卫生督办、数据统计。「任务调度」可切换任务路线／现场位置与校准，「卫生督办」可切换卫生巡检／卫生整改。服务消息从顶栏进入。
- 宿管可用账号或手机号登录、激活预置账号、恢复会话及退出。顶栏「账号安全」集中管理登录密码、手机号与恢复码。换绑时原手机号、新手机号的短信各自有 60 秒重发倒计时。宿管找回密码须验证绑定手机号并提供一次性恢复码。[账号维护和短信配置](../docs/17-账号与恢复运行手册.md)
- 可维护楼栋和房间档案，从房间详情查看关联入住与工单。为整栋楼建房时，用「保存并继续新建」逐间提交，保留楼栋、楼层、容量和启用状态，自动递增房号末尾数字。
- 学生档案及入住、调宿、退宿与历史。
- 工单筛选、处理时间线、受保护图片、接单、驳回、开始、进度说明、完工和返修。
- 卫生巡检支持四项评分、前次评分对照、同轮更正、图片、关联复查与作废留痕。日常巡检可用「保存并录入下一间」切到同层下一间启用宿舍。更正历史按中文字段列出修改前后的分值、等级或说明。[更正明细解析](src/utils/inspectionChanges.ts)
- 访客登记、超24小时状态、负责楼栋过滤、离访确认、按需查看联系方式及更正。
- 统计按授权楼栋和日期查询入住、工单、卫生及访客数据，可选近7天、近30天或本月。点击工单状态、报修类型或卫生等级分布图，可带原楼栋与日期条件下钻到对应明细。
- 多宿管路线支持正常交接与符合条件的异常接续。现场位置页提供设备会话、通行校准与地点二维码。地点码按 ISO/IEC 18004 生成 SVG，生成器零外部依赖，可复制扫码内容，或在独立窗口打印地点、楼栋楼层与二维码。[生成器](src/utils/qrcode.ts) · [地点码组件](src/components/mobility/AnchorCode.vue)
- 打开服务消息或查看相关记录会自动标为已读，支持将本页未读消息批量标为已读并同步顶栏角标。卫生整改支持责任人与期限、学生反馈、关联复查验收、退回与取消。
- 首次／重置改密引导与业务路由限制；官方纯文本AI研判展示、本人建议决策及结果留档。

所有写请求携带 Cookie 和 CSRF，业务提交带幂等键；网络重试复用同一内容对应的键，成功后清除。后台授权与版本校验仍是最终依据。图片先进行本地格式检查、缩放和重新编码，再上传鉴权接口；失败保留文字和待传图片，上传未完成时禁止提交业务表单。

生产部署需将 `dist/` 作为静态目录，并把 `/api/v1` 反向代理到 Java 服务；路由回退到 `index.html`，使用 HTTPS 与后端生产 Cookie 配置。Vite 开发服务器不作为生产部署方式。
