# 学生公寓平台界面与设计规范

本方案服务两类任务：宿管在电脑上批量管理、在现场快速记录；学生在手机上清楚地提交和跟进报修。视觉暂定名为「寓见 DormLink」，正式项目名称仍为学生公寓综合服务管理平台。日期：2026 年 11 月 7 日。

设计状态：用户已于2026年11月7日批准当前R3三端界面设计，作为后续Vue与ArkTS实现的视觉基线。本次批准针对界面设计；业务范围与验收仍以需求文档为准。

## 设计方向

采用「暖白服务台」与「暖黑服务台」两种可切换主题，界面按钮分别为「暖白日间」与「暖黑夜间」。日间以暖白纸面、炭黑文字与局部焦橙形成层次；夜间以暖黑背景、深石分区和浅沙文字保持相同气质。两种主题共用业务状态语义，绿色用于完成、琥珀用于待办、灰蓝用于办理中，状态始终配有文字。

视觉方向为温暖的编辑式极简：衬线标题建立内容气质，正文与表格保持清楚，房号和指标使用稳定的数字字形。主要层次由明暗、留白、细分隔与表面差异形成，焦橙只集中用于少数强调位置。

Web工作台使用扁平指标条，待办工单表作为主要工作区，楼层房间态势格作为次级概览；访客和卫生记录便于继续办理。学生首页以紧凑入住信息、庭院照片和明确的报修入口组织内容；宿管移动端以值班信息、待办人数和现场服务入口为主。

庭院照片用于表达自然光线与校园生活氛围，保留来源和许可入口，并标明为氛围示意，不代表平台服务学校的真实场景。图片来源、处理与署名要求见[图片资产说明](../design/assets/images/SOURCES.md)。

## 字体与布局

| 项目 | Web | 鸿蒙 |
| --- | --- | --- |
| 字体 | 本地Dorm Serif用于少量标题与品牌字，Dorm Plex用于正文，Dorm Chivo用于数字 | 延续字形层次，正文保持清晰并支持系统字号缩放 |
| 页面标题 | 当前桌面35 px，Dorm Serif 600；窄屏按内容长度收敛 | 24–28 fp，衬线字形仅用于少量短标题 |
| 区块标题 | 17 px，600 | 18–20 fp，600 |
| 正文与表单 | 正文与表格14 px；表单可按任务放大 | 正文与输入 16 fp，说明 14 fp |
| 数值 | Dorm Chivo，启用等宽数字；指标28–40 px，表格数字随正文 | 房号与数据保持稳定对齐，字号按窗口适配 |
| 行高 | 正文1.7，展示标题1.5 | 按原生文本测量，允许换行 |
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 px | 对应 4 / 8 / 12 / 16 / 24 / 32 vp |
| 圆角 | 控件4 px、内容表面6 px，扁平指标条以分隔组织 | 照片与触控区域适度柔和，避免多层容器叠套 |
| 布局 | 当前桌面212 px导航，主内容32 px内边距；详情抽屉 480–560 px | 单列，16–20 vp 边距，底栏不超过 4 项 |
| 反馈 | 按钮加载、就地错误、成功提示 | 相同语义，优先平台原生反馈 |

Dorm Serif是Noto Serif SC衍生的本地600字重子集，正文Dorm Plex来自IBM Plex Sans SC，数据Dorm Chivo来自Chivo。像素与vp/fp共用的是语义和比例；正式鸿蒙实现需根据设备、窗口和字号缩放适配。浏览器预览提供暖白／暖黑切换，切换不重新渲染业务表单，以保留当前输入；原生主题和字体仍需真机核验。字体来源、许可与子集范围见[字体资产说明](../design/assets/fonts/README.md)。

Web在1440/1280宽度优先呈现完整管理布局，窄屏按空间重排导航、指标条和内容列。复杂表格允许在自身容器横向滚动，并保留关键字段。手机设计以375–430 vp评审，平板使用居中内容或主从结构。固定底部按钮应留出系统手势区域，弹起键盘后仍能滚动到输入错误和提交按钮。

## 鸿蒙页面结构

学生底部导航建议为「首页、我的报修、我的」。首页先显示紧凑的当前入住信息，以庭院照片提供生活氛围，再明确展示提交报修入口、最近工单和本宿舍卫生记录。没有有效入住时，用「尚未关联宿舍，请联系宿管办理入住」代替可编辑房间选择。

报修表单的顺序为宿舍只读信息、标题、问题描述、故障图片、分类、联系方式确认、提交。标题、描述、分类和联系信息必填。AI 建议区域按需出现：选择图片/输入描述 → 主动请求 AI → 展示建议分类、建议标题、可补充问题 → 点击「采纳建议」写入可编辑字段。提交始终是独立动作。图片上传展示缩略图、单张进度、失败重试和删除；AI 失败保留所有已填内容。

工单详情展示房间快照、标题、当前状态、报修图片和时间线，待确认时出现「确认已解决」「仍未解决」；后者必须填写原因。学生在待受理状态可取消，已完成/已取消/已驳回隐藏后续办理按钮。

宿管底部导航建议为「工作台、工单、现场服务、我的」。移动首页以紧凑值班条显示身份与负责楼栋，随后显示待办工单数、在访人数，以及访客登记和卫生评分快捷入口。工单仅显示本人授权楼栋范围。访客登记保留必填字段和清晰的登记成功页；卫生页固定显示正在评分的楼栋房间，四项逐项录入并实时显示总分；工单办理页沿用同一状态线。

## 状态与组件规范

| 工单状态 | 标签文字 | 颜色语义 | 核心操作 |
| --- | --- | --- | --- |
| SUBMITTED | 待受理 | 琥珀 | 宿管接单/驳回，学生取消 |
| ACCEPTED | 已接单 | 蓝 | 办理宿管开始处理 |
| PROCESSING | 处理中 | 蓝 | 办理宿管填写结果并提交完工 |
| PENDING_CONFIRMATION | 待确认 | 琥珀 | 学生确认或反馈未解决；原办理宿管可带原因撤回结果返工 |
| COMPLETED | 已完成 | 绿 | 查看归档详情 |
| CANCELLED | 已取消 | 中性灰 | 查看归档详情 |
| REJECTED | 已驳回 | 红 | 查看原因，可新建关联报修 |

主按钮每个任务区只保留一个，文字准确表达动作，例如「保存评分」「登记来访」「提交完工」，避免泛称「确定」。次要操作使用浅底或线框。终态不显示不允许的操作；鉴权仍由服务端完成，按钮隐藏不构成权限控制。

表单必须有持续可见的标签、必填标记和就地错误；错误提供修复动作，例如「地面卫生应在 0–25 分之间」。双击提交期间禁用按钮并显示进度。退出有未保存内容的正式表单时提示保留或丢弃；网络失败保留草稿并允许重试。图片预览查看大图，关闭返回原来的滚动位置。

详情采用「基础信息 → 图片 → 处理记录 → 操作」的稳定顺序。每条时间线包含动作、操作者角色、时间、必要原因；AI 的建议和人工办理记录分别显示，避免建议看起来已经生效。

## 动效与可访问性

动效用于少量内容进入、按钮与抽屉反馈，使用opacity与transform，保持短促且不阻碍办理任务。背景与照片以稳定呈现为主；减少动态效果开启时移除非必要动画。键盘可访问导航、筛选、房间格、工单详情；对话框有名称、焦点管理、Esc关闭和返回触发按钮。成功与失败提示对读屏可感知。

手机按钮的项目设计目标为至少 48 vp 高、相邻控件留 8 vp；Web 表单按钮建议至少 40 px，触屏场景增大到 44–48 px。48 vp 是本项目的触控设计选择，不是把 WCAG 的 CSS 像素直接当鸿蒙单位。实施需检查系统字号放大、横屏、软键盘和安全区。

## 设计预览边界

[打开交互预览](../design/index.html)。预览使用浏览器 HTML/CSS/JavaScript 展示 Web 和鸿蒙视觉方向，支持主要导航、筛选和示例表单。所有数据均为示例，交互仅在内存中变化，刷新恢复；AI 按钮展示模拟建议，无真实模型调用。预览不是已完成的 Vue 工程，也不是可安装的鸿蒙 HAP。

正式实施时保留这里的任务结构、状态语义、颜色令牌和表单顺序；Vue 与 ArkUI 分别使用对应平台原生组件实现，不把 HTML 页面包装成鸿蒙 WebView 来代替 ArkTS 学生端。
