# 结构治理与联合回归

日期：2026-11-12。用户批准将已识别的可维护性问题一次完成。本轮基于已合并的设备辅助版本 `0522790`，沿用 R3 暖白／暖黑界面、openGauss 数据和公开接口。设备能力及真机限制仍以[14](14-设备感知重构与验收.md)为准；本文记录此次结构整理及新增回归。

## 职责与依赖

后端继续使用 Spring Boot 单体、JDBC 和显式事务，没有引入微服务、通用 CRUD 框架或每类一个接口／Impl。

- `repairs` 负责维修状态、责任变更、版本校验和进度历史。跨模块读取使用 `RepairSnapshot`，责任转交使用 `RepairTransfer`，不再公开数据库行 Map。
- `dispatch` 单向依赖维修能力。`DispatchService` 负责计划、看板和配置；`DispatchExecutionService` 负责认领、交接及出发／到达／受阻／恢复。
- 维修发布类型化 `RepairChanged`，调度以同步监听器维护任务投影。监听失败在原事务中传播；工单、进度、任务、审计和幂等记录整体回滚。这里依赖同步事件，不能擅自改成异步或提交后执行。
- 身份模块只发布 `SessionsRevoked`，调度和设备模块各自消费，不再由身份模块直接调用调度。SHA256 纯函数归入 `shared.crypto`，迁移不再引用身份服务。
- `MobilityService` 保留公开事务入口和视图组合；包内的 `MobilityWorkSessions`、`MobilityObservations`、`MobilityAnchors` 分别处理来源与租约、观测与位置、地点维护。SQL 集中到仓储的具名方法，JDBC 实例和行映射保持私有。
- 工作会话撤销按批读取，取消逐条补查；任务动作响应按单工单读取，不再扫描全部活跃工单。

架构测试同时扫描直接导入和完整限定引用，将 `shared.application`、`shared.jdbc`、`shared.api`、`shared.crypto` 分别纳入依赖图。当前业务包无依赖环；共享基础设施不得反向依赖业务包。`BusinessSupport` 仍是依赖身份的业务支持，并非无业务依赖的通用工具。

旧 HTTP 适配中的 Map 保留，以保护字段、空值和错误语义；本轮没有声称完成全域 DTO 重写。历史 SQL 与 V2／V3／V4 校验和文件未修改。

## 客户端状态与可读性

鸿蒙 `Index` 保留认证、主题、导航及组合；首页、报修、访客、巡检各自拥有控制器、草稿和视图。入口由 1141 行、70 多个状态收敛为 584 行、15 个状态，行数包含展开后的正常缩进，实际目标是明确状态所有权。

`ReadScope` 同时检查登录代际、请求代际和页面生命周期。首页预览、报修列表和详情拥有不同数据与加载状态；离页使旧读取失效，当前会话的 401 仍交给认证入口处理。公共入住上下文不随首页预览取消，服务端继续核对当前入住。

图片按 REPORT／RESULT／HYGIENE 草稿分别维护代际。清空或明确切换草稿后，旧选择、解码和上传回调不能写入新草稿；处理另一工单、开始另一宿舍复查时不沿用旧图片。其他用途的在途资源不受影响。

Web 的 `useLatestQuery` 统一负责网络取消、晚响应、错误和销毁，分别服务每个独立列表或详情。房间编辑、楼栋编辑、房间详情各自管理表单与读取生命周期；翻页不再重新请求楼栋列表。统计捕获已提交筛选快照，明细跳转不会使用尚未查询的筛选值。搜索选择框取消旧检索并在销毁时清理定时器。

全部维护中的 Vue／TypeScript／CSS 按锁定的 Prettier 3.6.2 格式化，生成代码由生成器负责。`npm run format:check --prefix web` 已加入 CI，防止重新出现一行数千字符的页面。

契约仍为 API 1.2.0，补齐 `PasswordRequest`、`LeaveRequest`、`ContactResult` 命名模型，三个生成端共有 87 个 schema。路径定义复用同一 schema，公开 JSON 和 API 1.1 兼容快照未变化。
