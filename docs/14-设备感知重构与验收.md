## 1. 实现与模块边界

Java仍是Spring Boot单体、Spring JDBC与显式事务。`cn.dormlink`根包仅保留启动和种子入口，业务按职责组织：

| 包 | 当前职责 |
| --- | --- |
| `identity` | 身份、真实登录会话和客户端渠道、密码与会话撤销事件 |
| `housing`、`repairs`、`fieldservice` | 档案入住、维修状态机、访客与巡检 |
| `dispatch` | 一致性看板、资格快照、短事务发布、任务执行与纯路线算法 |
| `mobility` | 主动工作会话、来源接管、观测质量、位置屏障和通行学习 |
| `media`、`assistance`、`reporting` | 私有图片、只读AI用例、授权SQL聚合 |
| `shared.api`、`shared.application`、`shared.jdbc` | 传输约定、少量共用事务／授权支持、JDBC与迁移 |

跨包公开实际使用的能力，内部辅助方法保留包内访问，没有为每类增加接口／Impl。新增设备API、位置与速度计算、规划输入和统计查询上下文使用明确类型；旧API1.1住房、工单、访客等仍保留Map适配以维持字段、空值与错误语义，**本轮不是全域DTO重写**。

API当前为1.2.0，共84个schema，三端由共享契约生成类型。`scripts/check-contracts.py`校验重生成无漂移，并对照`contracts/compatibility/v1.1.json`检查旧公开接口兼容。ID仍以字符串、时间以ISO8601传输。

## 2. 已完成的业务与性能修正

- 改密的BCrypt计算移出事务，以原密码摘要作条件更新；新密码落库与撤销全部会话同一事务，失败整体回滚。注销／改密通知设备模块失效对应工作会话。
- 普通命令缓存保存权限指纹；幂等重放重新核对当前角色、账号／学生资格与楼栋范围，权限变化后拒绝旧缓存。已有不含新指纹的历史缓存安全拒绝，客户端需刷新后使用新提交标识。
- 报修、巡检附件按页批量读取；最新处理说明批量查询。统计改为SQL聚合，保留授权、上海日期分桶、空结果和每房间最新有效卫生记录的原口径。
- 看板使用只读REPEATABLE READ快照，不持全局排他行锁；发布继续短事务锁与输入复核。人员与设备上下文按批读取，查询数量不随宿管逐人增长。
- 图片解码、清洗和缩放在JDBC事务之外，最多2个并行处理；生成最长边360px的真实缩略图，下载经过权限校验后以Resource流式输出。
- 临时图片每分钟按ID游标最多500条；删除失败保留墓碑并继续后续ID，原图与缩略图均成功删除后才移除无业务绑定元信息。BOUND历史附件不参与清理；过期幂等记录同样有批量上限。
- 调度变更事实随业务事务落库，内存仅保留O(1)重算提示。路线求解的初始插入与改进共享预算；耗尽时返回本次输入下验证过的安全部分结果及`BUDGET_EXHAUSTED`，保留冻结前缀和明确待安排原因。

## 3. 鸿蒙设备辅助与调度

宿管在原生端主动开启“现场辅助”，确认用途，服务器把工作会话绑定真实移动登录会话和来源代际。同账号另一个设备须明确接管；旧来源、旧代际和迟到回调不能覆盖新状态。Web可查看、暂停或结束本人会话，开启／恢复限移动端。

原生适配定位、计步、加速度、权限与系统定位开关、电量，以及带可见通知的持续后台定位任务。采集与异步UI有生命周期／来源栅栏，暂停、退出、权限撤回或后台任务被系统暂停时释放本次拥有的订阅与任务；低电量调整实际定位请求频率。服务端重新检查精度、时序和速度，缺失计步／速度以未知处理，不将缺失值当0。

批次最多20条、正文16KB；精细坐标只保留最新快照，短ACK和收件记录不保存坐标。通常约60秒后降级，120秒来源租约过期；年龄超过60秒或未来偏移超过5秒的观测不续租。失效数据立即退出调度，并由定时清理物理清空最新坐标；暂停／结束／撤销也清理坐标。收件记录保留约24小时、通行片段约30天后分批删除；批处理积压和停止服务会推迟物理清理，不能将逻辑TTL描述成磁盘即时擦除，备份也有独立保留周期。

GPS可在已核验入口坐标范围内提示楼栋，不能证明楼层／房间。设备新观测识别B栋、楼层未知时，会覆盖旧A栋3层；失效后保留观测时间屏障，不能静默恢复已被否定的旧手动点。只有更晚的明确人工位置设置可以覆盖。规划缺少楼层时返回`POSITION_REQUIRED`，不把0或1伪装成真实楼层。

活跃宿管按账号去重：有效前台心跳或有效ACTIVE设备工作租约均可证明活跃；接单意愿、楼栋范围和可用时段仍单独校验。设备原始事件不直接调用求解器；有意义的位置、资格或有效通行成本变化才参与重算。模型新增、停用和过期都进入排序后的成本指纹，恢复人工基线后会重新规划。

共享通行估算只学习已配置方向上、双端近期确认入口和显式出发／到达之间的片段，并核对目标工单楼栋。至少5段、3个独立工作会话，每会话贡献有上限，异常段排除；模型有版本记录，宿管可在授权两端楼栋内恢复人工基线。没有实测路径长度时，**不会把人工分钟数除以设备速度来推算新分钟数**；定位与速度不是考勤、绩效或自动接单／到场／完工依据，也不默认发送给AI。

学生端提供系统拍照、扫码核对本人入住楼栋和已确认预约的系统日历／通知入口。扫码只能预览已登记且有权访问的地点，静态码可被复制，不证明物理到场；报修仍绑定本人当前入住。日历通过系统编辑器由用户确认保存，本地通知不等于应用关闭后可接收新服务端工单。当前没有核验校园坐标，种子锚点坐标应保持空值，不能据此承诺自动识别校园楼栋。
