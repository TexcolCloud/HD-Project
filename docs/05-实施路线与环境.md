## 本机运行脚本

| 脚本 | 行为 |
| --- | --- |
| scripts/start-database.ps1 | 默认从deploy/.env.opengauss检查OG_HOST／OG_PORT的TCP可达；不冒称SQL登录通过；-Database mysql保留旧容器启动行为 |
| scripts/run-backend.ps1 | 默认-Database opengauss读取deploy/.env.opengauss；支持mysql/local；-BuildOnly无需环境文件，-SkipBuild复用成功产物；独立运行JAR避免Windows锁住target |
| scripts/migrate-database.ps1 | 从忽略的源／目标配置读取连接，-SelfTest执行隔离JDBC自测，-CheckOnly只预检；实际迁移须停源API写入，并拒绝非空目标业务表 |
| scripts/run-web.ps1 | 首次npm ci，再启动127.0.0.1:5173；/api代理到8080 |
| scripts/run-harmony.ps1 | 生成模型、构建HAP；非BuildOnly时检查设备，复用既有8080转发再安装启动；可指定-Target |
| scripts/acceptance-api.py | 对运行中的真实后端执行10组HTTP验收；openGauss使用--report output/acceptance/opengauss-api-results.json保留MySQL旧报告；增加虚构记录，不清库 |
| scripts/acceptance-dispatch.py | 真实调度HTTP7组；openGauss使用--report output/acceptance/opengauss-dispatch-api-results.json；关闭标记测试单并恢复设置，旧过期截止清空而非重写历史 |

后端直接Maven启动默认local／H2；项目启动脚本默认openGauss，二者不是同一业务库，不能把切换profile当成数据迁移。配置模板为 `deploy/opengauss.env.example`，复制到被忽略的 `deploy/.env.opengauss`；SSH管理凭据不会传给应用进程。Web、后端和设备继续共用同一/api/v1契约。
