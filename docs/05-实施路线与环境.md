## 本机运行脚本

| 脚本 | 行为 |
| --- | --- |
| scripts/start-database.ps1 | .env不存在时生成本机随机数据库凭据，启动MySQL并等待健康；不覆盖现有环境文件 |
| scripts/run-backend.ps1 | 加载环境、打包测试，再以mysql profile运行；-BuildOnly只打包，-SkipBuild复用已成功产物；复制独立运行JAR避免Windows锁住target |
| scripts/run-web.ps1 | 首次npm ci，再启动127.0.0.1:5173；/api代理到8080 |
| scripts/run-harmony.ps1 | 生成模型、构建HAP；非BuildOnly时检查设备，复用既有8080转发再安装启动；可指定-Target |
| scripts/acceptance-api.py | 对运行中的真实后端执行10项HTTP验收，写output/acceptance/api-results.json；增加虚构记录，不清库 |
| scripts/acceptance-dispatch.py | 真实调度HTTP7组检查；生成标记测试单并关闭本轮单据，结果写dispatch-api-results.json，不清业务数据库 |

后端local profile使用H2文件库，启动方式见[后端README](../backend/README.md)。正常跨端演示使用上述脚本的MySQL profile，避免在不同数据库间误认数据丢失。Web、后端和设备均采用同一/api/v1契约。
