# 学生公寓平台开发与验收

记录日期：2026年11月7日（Asia/Shanghai）。Java、Vue 与原生 ArkTS 工程已实现，使用真实 SQL 与统一 API；本记录区分自动化检查、应用内浏览器操作和模拟器运行。待测项须完成实际操作后再改为通过。

## 运行与契约

在项目根目录按顺序执行，后端和 Web 分别占用一个持续运行的终端：

```powershell
.\scripts\start-database.ps1
.\scripts\run-backend.ps1
```

```powershell
.\scripts\run-web.ps1
```

Web：[http://127.0.0.1:5173](http://127.0.0.1:5173)；后端：[http://127.0.0.1:8080/api/v1/health](http://127.0.0.1:8080/api/v1/health)。数据库为 MySQL 8.4.13，固定镜像摘要见 [compose.yaml](../deploy/compose.yaml)，仅映射本机 `13306`。凭据位于被忽略的 `deploy/.env`，不复制到验收记录。

DevEco 启动 Pura 90 模拟器后执行：

```powershell
.\scripts\run-harmony.ps1
```

脚本调用 DevEco 配套工具，生成模型、构建 HAP、检查设备、建立8080端口转发并安装启动。默认目标 `127.0.0.1:5555`；可传 `-Target`。Bundle：`com.dormlink.residence`；Ability：`EntryAbility`；产物：[entry-default-unsigned.hap](../harmony/entry/build/default/outputs/default/entry-default-unsigned.hap)。目前未签名调试包用于本机模拟器，未完成真实手机签名及运行验证。

当前契约见 [API说明](../contracts/API.md) 与 [openapi.json](../contracts/openapi.json)。Web 构建时生成 TypeScript 类型；鸿蒙构建脚本先生成 ArkTS 模型。实际 SQL 为 [schema.sql](../backend/src/main/resources/schema.sql)，当前采用初始 `CREATE TABLE IF NOT EXISTS`，重复启动不清库；后续结构升级需要新增版本化迁移。

AI协议测试使用明确的本地 HTTP fixture，验证文本、base64图片、结构化响应及非法响应降级，不发送真实供应商请求。

## AI配置与交付边界

当前使用官方地址 `https://api.deepseek.com`，模型ID `deepseek-flash`（V4.1 Flash）。在现有 `deploy/.env` 填写 `AI_API_KEY` 后重启后端；可参考 [.env.example](../deploy/.env.example)。当前密钥为空，真实DeepSeek调用、账号额度与多模态输出尚未验收。已验证未配置时返回503，保留手工报修；本机HTTP协议测试不是官方调用成功记录。

调用量默认每人每日10次、每分钟2次、全局并行2个、超时15秒；供应商实际费用与账号额度由供应商后台管理，本项目未实现币种费用日/月预算。只发送用户主动同意的故障文字和最多3张图片，建议必须经学生采纳并主动提交。

当前交付范围为单校、单实例、按房间容量管理，无独立床位；宿管授权由受控初始化维护。数据库与附件需配套备份，尚无生产部署、备份恢复演练、真实手机验收或需求目标规模性能测量记录。设计原型及设计阶段验证保留于 `design/` 与[设计验证记录](06-设计验证记录.md)，不作为当前业务应用入口。
