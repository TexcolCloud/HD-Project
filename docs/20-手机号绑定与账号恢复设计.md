# 手机号绑定与账号恢复设计

关联 [Issue #6](https://github.com/TexcolCloud/HD-Project/issues/6) 的号码格式讨论。本次交付设计覆盖 Java 后端、Vue 宿管端与鸿蒙学生及宿管端。手机号登录、注册激活、绑定换绑、自助找回、人工恢复及配套验收一并交付。

## 账号与号码

| 概念 | 在系统中的用途 |
| --- | --- |
| 账号 ID `sys_user.id` | 学生档案、会话和权限继续关联同一个稳定 ID。更换号码或密码后，仍可查询原有个人业务记录。 |
| 用户名 `sys_user.username` | 保留现有登录方式。新建学生档案时以学号初始化用户名，之后若更正档案学号，仍以实际登录用户名为准。 |
| 登录手机号 | 学生或宿管通过短信核验后获得的登录标识。输入手机号和密码可登录，绑定的号码也可用于找回密码。 |
| 业务联系号码 | `student.phone`、访客号码和报修联系号码继续由各业务功能维护。它们可以重复，填写或修改不会触发账号绑定。 |
| 恢复码 | 宿管保存在设备外的一次性凭据。宿管自助找回时，需要同时证明能接收绑定手机号的短信并持有恢复码。 |

同一手机号仅可绑定一个账号，约束覆盖学生和宿管。旧账号从未绑定状态开始，可继续使用用户名登录。短信确认申请人当时能接收该号码的验证码。学校通过学生建档及宿管岗位审批确认身份和角色，宿管的楼栋范围仍由维护人员授予。相关实现见 [学生档案服务](../backend/src/main/java/cn/dormlink/housing/HousingService.java)、[认证服务](../backend/src/main/java/cn/dormlink/identity/AuthService.java) 和 [账号与恢复运行手册](17-账号与恢复运行手册.md)。

## 用户流程

| 场景 | 学生与宿管操作 | 后端结果 |
| --- | --- | --- |
| 注册并激活 | 选择「注册 / 激活」，输入学校提供的账号和临时密码。验证手机号并设置新密码。宿管保存仅展示一次的恢复码。 | 学生通过学校建档获发账号，宿管通过审批获发账号及楼栋授权。两类账号都可使用现有工具签发的 24 小时临时密码。激活时绑定号码、保存密码、撤销旧会话，并为宿管签发恢复码。角色、楼栋和档案取自原账号。 |
| 已有账号绑定 | 登录后在「账号安全」输入当前密码，验证要绑定的手机号。宿管同时保存恢复码。 | 在唯一约束下绑定并显示掩码号码。已有绑定时引导换绑。 |
| 手机号登录 | 在登录页选择「手机号」，输入手机号和密码。 | 手机号解析为绑定的账号 ID，然后复用密码验证、会话签发和业务授权。原有账号方式继续可用。 |
| 忘记密码 | 输入绑定手机号并验证短信，设置新密码。宿管还须输入恢复码。 | 短信验证通过后签发限时重设凭据。重设成功后撤销 Web 与鸿蒙旧会话。宿管的恢复码随成功重设一起消费，重新登录后可在「账号安全」生成新码。 |
| 更换手机号 | 在「账号安全」输入当前密码，并分别验证旧号和新号。 | 通过后原子更换号码，撤销旧会话和待用验证码。宿管换绑时旧恢复码失效，并签发新码。新号已被占用时原绑定继续有效。 |
| 人工恢复 | 遗失号码、未绑定、长期无法收码或宿管丢失恢复码且无法登录时，联系学校核验身份。 | 维护工具按账号版本操作，受控解除失去控制的绑定并重新签发临时密码。恢复使用同一账号，保留档案、角色和范围。每次操作有审计，停用账号须先走已有的启用审批。 |

Web 宿管登录页与鸿蒙双角色登录页均提供「账号 / 手机号」切换、「注册 / 激活」和「忘记密码」，账户菜单内提供「账号安全」。页面沿用现有登录和首次改密样式，提供脱敏号码、验证码重发、过期或收码失败提示及人工联系入口。首次短信校验通过后才根据服务端响应展示宿管恢复码输入。Web 管理端仅向宿管开放，鸿蒙按服务端返回的角色进入相应工作区。已建档且启用的学生可在入住前激活。短信不可用时，已有受控临时凭据仍可用于受限登录和首次改密，待可收码时可在「账号安全」绑定。现有入口见 [鸿蒙页面](../harmony/entry/src/main/ets/pages/Index.ets)、[Web 登录页](../web/src/pages/LoginPage.vue) 和 [账号维护入口](../scripts/account-maintenance.ps1)。

## 契约和实现

以下均为 `/api/v1` 下的接口。Vue 与 ArkTS 的模型由共享契约生成。错误复用现有响应结构，挑战 ID 作为不透明字符串传输。[接口说明](../contracts/API.md) · [契约生成器](../contracts/generate_openapi.py)

| 接口 | 调用条件与行为 |
| --- | --- |
| `POST /auth/login` | 增加可选 `identifierType`，取值 `USERNAME` 或 `PHONE`，缺省 `USERNAME`。沿用现有必填 `username` 作为标识输入字段。两种方式分别查询，服务端在会话签发前复核密码、账号版本和当前号码绑定。 |
| `POST /auth/phone/challenges` | 申请 `ACTIVATE`、`BIND`、`CHANGE_PHONE_OLD`、`CHANGE_PHONE_NEW` 或 `REPLACE_RECOVERY_CODE` 用途的短信验证。挑战绑定账号、发起会话及用途。激活要求未绑定且持有维护工具签发的有效临时凭据对应的会话，其余用途需正常会话并核验当前密码。旧号及恢复码重签用号码由服务端从当前绑定读取。 |
| `POST /auth/activate` | 受限会话提交挑战 ID、验证码和新密码。通过时一次完成首次改密和绑定。宿管响应额外包含仅当次展示的恢复码。 |
| `POST /auth/phone/bind` | 正常会话提交挑战 ID 和验证码，完成首次绑定。若账号已绑定则引导换绑。宿管响应包含恢复码。 |
| `POST /auth/phone/change` | 正常会话提交旧号和新号各自的挑战 ID 与验证码。两条挑战须属于同一账号、会话及账号版本。换绑和两条验证消费同事务完成，宿管响应包含新恢复码。 |
| `POST /auth/recovery-code/replace` | 正常宿管会话提交对应挑战 ID 和验证码，重新生成恢复码，旧码及进行中的找回一并失效。 |
| `POST /auth/password-recovery/challenges` | 公开入口。号码格式正确的请求统一返回同样结构的申请结果和挑战 ID。仅向满足恢复条件的账号投递短信。 |
| `POST /auth/password-recovery/verify` | 校验挑战 ID 和短信验证码。通过后一次性消费短信挑战并返回短时重设凭据和是否需要恢复码，仅对已完成短信验证的持有者提供流程信息。 |
| `POST /auth/password-recovery/complete` | 提交重设凭据、新密码及适用的恢复码。后端根据账号角色、启用状态、版本和当前绑定验证，在成功重设时一并消费重设凭据及适用的恢复码。失败响应统一，成功后重新登录。 |
| `GET /auth/me` | 增加可选 `phoneMasked` 和宿管 `recoveryCodeConfigured`，只反映当前账号自己的绑定和恢复码状态。 |

认证域复用现有密码策略、账号版本、会话撤销与审计流程。激活、换绑、密码找回和人工恢复在同一事务更新账号、消费相关凭据并撤销旧会话。应用端复用会话撤销事件，提交后结束旧宿管工作会话并清理最新位置，触发调度重算。维护工具保留同事务清理路径。两种路径验收相同的旧会话及设备数据失效结果，工单责任和历史继续按现有规则接续。首次绑定、恢复码重签、启停、改密及楼栋授权调整均使既有挑战与重设凭据失效。

所有申请及提交从服务端账号或令牌解析主体，重设所需凭据由服务端按角色确认。Web 管理端的登录和恢复按宿管角色校验，Cookie 写请求保留 CSRF 防护，匿名找回复用登录页的 CSRF 初始化。鸿蒙正常会话复用 Bearer，匿名请求仅用于申请、验证和完成找回。首次改密的受限会话仅额外放行激活用途和激活提交。Web 与鸿蒙收到撤销后的会话失效响应时，清理登录态及页面敏感临时输入，已有草稿继续按账号隔离。[认证过滤配置](../backend/src/main/java/cn/dormlink/identity/SecurityConfig.java)

## 存储、短信和恢复

- 在 `sys_user` 增加可空的唯一 `login_phone` 和配对的 `login_phone_verified_at`，通过 openGauss 与 MySQL/H2 的同版本增量脚本上线。旧行保持空值。国内手机号按去除首尾空白后的 11 位 ASCII 数字入库。手机号唯一性由数据库约束，停用账号的绑定保留至人工确认解除。
- 验证记录保存不透明 ID、验证码的带密钥校验摘要、用途、目标账号和号码、签发时账号版本、有效期以及尝试与消费状态。重设凭据以随机令牌签发，服务端仅保存摘要并核对同一账号、号码和版本。验证码及重设凭据一次有效，默认 5 分钟过期，验证码同号码 60 秒重发间隔，每个挑战最多尝试 5 次。重发后同一流程只有最新签发的验证码有效。按来源、目标号码、账号和系统配额限制发送及验证，失败计数独立持久化。手机号和用户名登录共享已识别账号的失败额度。
- 宿管每次只保有一枚有效恢复码，使用安全随机数生成，后端仅保存校验摘要。恢复码可在激活、首次绑定及换绑时发放，也可在「账号安全」中使用当前密码和已绑定手机号重签。明文仅在成功响应展示一次，页面提醒离线保存。激活、换绑后展示完毕再返回登录页。结果丢失时，用户可用已设置的密码重新登录后重签。人工重置可同时收回遗失号码的绑定和恢复码，重新收码验证后再发放。
- 公开找回接口为有效格式的号码统一返回「如果该号码可以找回密码，验证码将发送到此号码」。号码未绑定、已停用或正在人工恢复时也返回相同提示。短信投递移出请求链路，由并发和容量受限的任务调用供应商，避免发送耗时泄露账号状态。发送失败或超时可重新申请，原绑定和密码继续有效。生产环境只记录脱敏标识、操作结果和审计所需的账号 ID，密钥和短信模板由部署配置注入。开发和集成环境使用隔离的测试发送器，验证码通过测试通道核验。[OWASP 密码找回指南](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)
- 已验证号码随账号备份。恢复完成后清理所有验证码和重设凭据，撤销旧会话及备份里的宿管恢复码，宿管核验并重新申领以防旧码复活。人工管理通过现有 `reset-password` 操作加显式清除绑定选项和版本检查，同事务追加审计。短信可能受到号码回收、SIM 换卡及号码携转影响，学生保留人工核验通道，宿管自助重设需要恢复码。[NIST SP 800-63B-4 电话网络认证约束](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/)

## 交付与验收

同次交付包含数据库增量迁移、OpenAPI 与模型生成、认证域、Vue 和 ArkTS 页面、短信配置、维护工具、恢复脚本及运行手册。开发验证使用测试发送器。真实投递验收须配置所选供应商与模板，并使用获准的测试号码核对注册、换绑和找回短信。供应商和测试号码由实际部署配置提供。

| 验收对象 | 可判定结果 |
| --- | --- |
| 原账号与新标识 | 旧版客户端在各自业务端原样登录。手机号和用户名指向同一账号及业务历史，数字用户名与手机号相同也按选择的登录方式解析。Web 阻止学生登录管理端，宿管获准的楼栋范围和原有记录保留。 |
| 受控激活 | 已建档未入住学生可激活原账号。宿管激活后保留审批楼栋。未预置、停用或临时凭据过期时拒绝激活，表单无法授予角色或楼栋。不同角色并发绑定同号时只有一个成功。 |
| 绑定与换绑 | 编辑业务号码无认证副作用。缺少旧号或新号任一验证、重复或跨账号提交、并发占用、账号版本变化均拒绝。换绑成功后旧号码和旧会话失效，新号码登录仍获得相同业务权限。 |
| 密码找回 | 公开申请对未绑定、停用和可找回号码返回相同结构。密码重设前拦截过期、重放或跨用途凭据。学生短信验证可重设，宿管仅提交短信验证或旧恢复码时失败。重设成功后旧密码和旧会话均失效。 |
| 人工恢复与调度 | 人工核验、版本检查、审计及临时密码恢复完整。宿管旧工作会话结束并触发调度重算。停用再启用或备份恢复后旧验证凭据无法使用，历史业务数据可查。 |
| 客户端验收 | 在应用内浏览器验收 Vue 宿管流程，在 DevEco 模拟器分别验收学生和宿管流程。各自完成激活、既有账号绑定、两种登录、找回、换绑及人工入口，核对 Web CSRF 和移动会话，覆盖短信不可用和恢复码遗失。 |

后端回归以 [账号生命周期集成测试](../backend/src/test/java/cn/dormlink/AccountLifecycleIntegrationTest.java) 为起点。
