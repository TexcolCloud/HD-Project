# 学生公寓综合服务管理平台

文档同步日期：2026-11-25，核对基线为 `main @ 522344f`。API 1.3.0 支持调度时间纠偏、异常接续、服务消息、卫生整改和 AI 建议反馈。当前导航、浏览器与模拟器验证见[界面收敛与交付版本](docs/18-界面收敛与交付版本.md)。业务闭环、账号维护和历史架构验收分别见[服务闭环与联合验收](docs/16-服务闭环与联合验收.md)、[账号与恢复运行手册](docs/17-账号与恢复运行手册.md)、[结构治理](docs/15-结构治理与联合回归.md)及[设备验收边界](docs/14-设备感知重构与验收.md)。11／12 保留批准时的扫描与设计依据。

「寓见 DormLink」包含Java后端、Vue宿管管理端和原生ArkTS/ArkUI鸿蒙应用。学生图文报修并跟进工单，宿管办理入住、报修、访客和卫生；新增多宿管动态路线与只读AI研判／值班简报。三端共用数据库、权限与契约，沿用已批准R3暖白／暖黑设计。

Web 入口：[http://127.0.0.1:5173](http://127.0.0.1:5173)。启动后端与 Web 后打开，使用宿管账号登录。API 为 [http://127.0.0.1:8080/api/v1](http://127.0.0.1:8080/api/v1)，健康检查为 [/health](http://127.0.0.1:8080/api/v1/health)。

## 本机启动

在项目根目录使用 PowerShell 和 Docker Compose。运行下列命令可直接启动本机 openGauss、Java API 和 Nginx Web。首次启动会生成独立随机口令，保存在 Git 忽略的 `deploy/.env.opengauss`；空业务库会初始化演示数据。

```powershell
.\scripts\run-containers.ps1

# 局域网联调模式：向同一局域网其他主机开放 Web（5173）与鸿蒙 API（8080），数据库仍仅绑定 127.0.0.1
.\scripts\run-containers.ps1 -Lan
```

默认模式下 Web、API、数据库分别监听本机回环地址的 5173、8080 和 15432 端口；`-Lan` 模式会通过宿主机转发开放 `0.0.0.0:5173` 与 `0.0.0.0:8080`（兼容 WSL2 `Mirrored` 网络与公用防火墙配置）并放行私网跨域请求，供同一局域网下的其他电脑浏览器及鸿蒙模拟器／真机测试（鸿蒙登录页底部「服务连接设置」填入 `http://<开发机局域网IP>:8080`）。数据库和附件分别保存在命名卷中，`run-containers.ps1 -Down` 停止容器与局域网转发并保留卷。请随数据库备份妥善保存本地口令文件。

开发时可只启动数据库容器，再在宿主机运行后端和 Web。脚本会检查应用账号的 SQL 登录，准备 PG 兼容的业务库和十个隔离测试库。如需使用外部 openGauss（含既有 VMware／openEuler 环境），按[配置模板](deploy/opengauss.env.example)填写远端 `OG_HOST`、端口与应用凭据；此时该脚本只探测 TCP，SQL 登录由 API 健康接口确认。

```powershell
.\scripts\start-database.ps1
```

分别在两个终端启动后端与 Web；两条命令都需要保持运行：

```powershell
# 终端一：打包、测试，再以openGauss配置启动API
.\scripts\run-backend.ps1
```

已经成功打包、只需重启时可用 `-SkipBuild`；脚本会复制到独立运行JAR，避免Windows锁住target产物。`-BuildOnly`只构建，不要求数据库环境文件。openGauss 与 MySQL／H2 分别维护初始 `schema.sql` 及有序 V2 至 V8 迁移，并逐版本校验 checksum；不要改写已应用脚本或清库。

旧MySQL容器、命名卷及 `deploy/.env` 保留为迁移源；需要显式使用旧库时运行 `start-database.ps1 -Database mysql` 和 `run-backend.ps1 -Database mysql`。旧数据迁移须先停止旧API写入，再按[迁移说明](docs/10-openGauss迁移与验收.md)执行工具；目标已有业务行时工具会拒绝覆盖。

```powershell
# 终端二：首次按锁文件安装依赖，再启动 5173
.\scripts\run-web.ps1
```

在 DevEco 启动现有 Pura 90 模拟器，然后运行：

```powershell
# 生成共享契约模型、构建、安装并启动鸿蒙应用
.\scripts\run-harmony.ps1

# 仅构建时使用
.\scripts\run-harmony.ps1 -BuildOnly
```

鸿蒙脚本默认目标为 `127.0.0.1:5555`，通过 hdc 把设备 8080 转发到开发机。其他已连接目标使用 `-Target '设备标识'`。App 的「服务连接设置」可修改 API 地址，默认 `http://127.0.0.1:8080/api/v1`。当前 HAP 位于 `harmony/entry/build/default/outputs/default/entry-default-unsigned.hap`，Bundle 为 `com.dormlink.residence`，Ability 为 `EntryAbility`；已在本机模拟器安装，真实手机及发布签名另行配置。

## 动态多宿管路线

宿管 Web 侧栏分四个业务域、共八个入口，从「维修与调度」组的「任务调度」进入 `/dispatch`。鸿蒙可点底栏「路线」或首页「查看下一站」进入「本次路线」。人员数由有效会话心跳或有效ACTIVE设备工作租约按账号去重，不能手填人数。本人可维护接单意愿、授权范围内位置与可用截止时间；新工单或人员变化会重排可行剩余路线，保留在途／现场前缀和既有办理责任。没有可行方案时展示待安排原因。

路线推荐与实际认领分开，出发／到达／受阻／恢复也不代替维修开始、完工和学生确认。Web与鸿蒙均提供正常交接，限原办理人尚未开始且未在途／到场的已接单工单；原负责人停用、失去楼栋资格或失联超过宽限时，可由有资格宿管带原因明确异常接续，接续后先核对现场再恢复任务。调度时间边界、个人通行校准和当前验收见[16](docs/16-服务闭环与联合验收.md)，原调度设计与验收保留在[09](docs/09-动态调度交付与验收.md)。

## 现场辅助与系统能力

宿管可在鸿蒙主动开启／暂停／结束现场辅助，使用定位、运动传感器和人工／扫码锚点提供调度依据。GPS不证明楼层；未知或过期位置要求确认，不恢复已被新设备观测否定的旧手动点。共享通行估算达到跨会话样本门槛才覆盖人工基线，可按版本恢复基线。Web可查看本人工作会话、锚点和模型，并暂停／结束本人采集。

学生端增加系统拍照、扫码核对入住楼栋、系统日历／通知入口。静态码可以复制，不能证明到场；报修仍绑定本人当前入住。当前只有模拟器，GPS／计步／熄屏持续任务与耗电的真机效果未验证；没有核验校园坐标，不能承诺自动楼栋定位。详见[实施与验收边界](docs/14-设备感知重构与验收.md)。

## AI 助手

后端已接入 DeepSeek 官方接口适配，默认模型 ID 为 `deepseek-flash`（V4.1 Flash）。openGauss启动方式在 `deploy/.env.opengauss` 中配置 `AI_API_KEY`，可按[配置模板](deploy/opengauss.env.example)调整 `AI_BASE_URL`、`AI_MODEL` 与 `AI_DAILY_LIMIT`，然后重启后端；保留原有数据库配置，密钥只留本机。显式MySQL方式仍读取 `deploy/.env`。

学生助手产生可采纳的填写建议；宿管可主动生成单单研判和文字值班简报，显示服务端事实及授权工单引用。二者共用HTTP、配额、审计和幂等账本，重放相同请求不重复外部调用；AI没有派单、预约或状态写权限。当前已完成DeepSeek官方纯文本工单研判及Web页面展示、人工反馈留档的实际联调；附图研判、值班简报的官方调用和真实维修效果未验收。本地HTTP fixture仍只证明协议、权限／脱敏和缓存行为，逐项证据见[16](docs/16-服务闭环与联合验收.md)。
