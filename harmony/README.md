# 寓见鸿蒙应用

原生ArkTS / ArkUI Stage工程，一个entry HAP按登录账号返回的角色展示学生或宿管界面。没有WebView、内存假接口或AI模拟回复。设计沿用已批准的暖白／暖黑方案。

## 构建与运行

在项目根目录执行：

```powershell
./scripts/run-harmony.ps1 -BuildOnly
./scripts/run-harmony.ps1
```

脚本使用 DevEco Studio 6.1.1 配套的 Node、SDK 和 Hvigor，先从共享 OpenAPI 生成 ArkTS 接口，再构建 HAP。工程锁定 modelVersion 6.1.1、HarmonyOS SDK `6.1.1(24)`。设备验收前需启动 Pura 90 模拟器。

- Bundle：`com.dormlink.residence`。
- Ability：`EntryAbility`。
- 产物：`entry/build/default/outputs/default/entry-default-unsigned.hap`。
- 本机模拟器可安装该调试未签名包；真机和正式发布需要独立签名配置。

后端应先运行。模拟器通过`hdc rport tcp:8080 tcp:8080`连接宿主机服务，默认API地址`http://127.0.0.1:8080/api/v1`；登录页的「服务连接设置」可改为局域网或HTTPS服务地址。修改服务地址后应退出当前会话重新登录。

开发种子账号为 `student1`／`student2`／`student3` 和 `manager1`／`manager2`。账号角色、本人数据和楼栋范围均由后端决定。本地登录说明见[共享接口契约](../contracts/API.md)。

## 已接入业务

学生底栏为「首页／我的报修／我的」。宿管底栏为「首页／路线／工单／巡检访客」，第四项可切换卫生巡检、卫生整改与访客登记。顶栏可进入「消息」和「我的」，支持刷新的页面另有「刷新」。二级详情和表单收起底栏，返回时按导航栈恢复上一页、业务上下文与滚动位置。宿管也可从首页「查看下一站」进入「本次路线」。首页的「值班简报」和工单的「AI研判」提供只读辅助。[模块与接口](FEATURES.md)

当前 `Index` 负责认证、主题、导航和组合；首页、报修、访客、巡检、服务消息与整改各自位于 `features/`，查询通过 `ReadScope` 检查请求与页面代际。当前闭环及设备逐项验收见[16](../docs/16-服务闭环与联合验收.md)，[15](../docs/15-结构治理与联合回归.md)保留前次结构治理历史。公共入住上下文属于登录会话；离开首页不会使报修创建丢失当前宿舍。图片按用途退役旧回调，换工单或复查房间不沿用其他草稿图片。

- 学生：当前宿舍与入住历史、图文报修、紧急原因、联系时段、分类与优先级、AI建议主动调用及采纳、本人工单筛选／分页／时间线、上门预约状态和北京时间、取消／确认／未解决反馈、本人入住期间卫生记录。
- 宿管：真实工作摘要、访客登记／楼栋筛选／离访确认／来访详情、巡检日期选择和实际时间补录、上次评分对照、带原因更正与关联复查、工单查询／接单／开始处理／追加说明／完工凭证／驳回／返修。
- 服务跟进：点开未读消息自动标记已读，也可将本页未读消息批量标记。宿管点击访客消息直达对应的 `visitor-detail`。责任学生可提交整改说明与图片，宿管关联合格复查后验收或退回，也可调整责任期限或带原因取消。
- 责任与建议：宿管正常交接和受资格约束的异常接续；AI建议的本人采用／修改／忽略及结果留档；通行样本不足时明确未知，不展示虚构节省。
- 出行辅助：宿管主动开始／暂停／结束独立工作会话，位置和运动权限只在开启后申请；支持人工锚点、ScanKit地点预览确认、位置来源／精度／新鲜度、步行速度或未知状态、同账号来源接管。拒绝设备权限仍可人工确认锚点与办理工单，不增加在线人数，也不自动接单／到达／完工。
- 系统能力：LocationKit连续定位、SensorServiceKit计步差分与短时运动标志；明确开启后台模式后申请LOCATION持续任务和系统可见通知，暂停／结束／撤权停止。学生不持续采集位置，只按需扫码核对当前入住楼栋／楼层。已确认预约可主动打开系统日历创建页，通知可主动授权并测试。
- 日期与列表：上门时段、巡检时间、接单截止和整改期限使用原生日期或时间选择器，并提供常用时段。首页、宿管路线、报修、访客、卫生、整改与消息等可刷新页面共用原生下拉 `Refresh`。报修、访客、巡检、整改和消息列表翻页后回到顶部。
- 附件：上传后的图片按三列网格展示。内嵌图片优先取缩略图，展开半模态预览时再加载独立高清图。[图片来源选择](entry/src/main/ets/services/ImageSource.ets) · [SecureImage](entry/src/main/ets/components/SecureImage.ets)
- 图片处理：系统PhotoViewPicker和CameraPicker共用图片草稿控制器。异步文件描述符直接解码、单图处理，长边不超过1800像素，显式不打包元数据；逐张私有上传，失败保留并可重试／移除。旧账号选图、拍照、上传结果和销毁后的PixelMap不能写回新页面。
- 账号与会话：学生和宿管均可用账号或手机号登录、激活预置账号、在「我的」进入账号安全并换绑。学生用短信找回密码，宿管还须输入一次性恢复码。MOBILE Bearer、密码、短信验证码和恢复码只在流程所需的内存中使用。退出、401、激活、换绑和改密后清理当前会话。服务地址和主题可保存在应用私有偏好设置中。[账号设计](../docs/20-手机号绑定与账号恢复设计.md)
- 草稿与未决提交：报修、访客、巡检文字草稿按服务地址及账号隔离，限期保存在应用私有空间；不保存密码、令牌、图片字节或AI外发同意。结果未知时保留幂等键，先核对已有记录，再明确清除草稿才重填，不能改正文悄悄另起操作；明确校验拒绝可修正，访客重复确认作为显式新请求。成功后释放旧键，操作中禁用重复提交，恢复后图片需重选，网络恢复不会自动提交。
- 消息提醒：前台轮询在隐藏、退出或换号后停止；本地系统提醒由用户开启，只概括新消息。应用被终止后的新服务端消息不属于本地通知能力，尚未接入远程PushKit。

访客超24小时且仍在访时，由服务端在查询中标记，客户端在列表和详情显示状态。保存离访前核对访客、房间及当前记录版本。访客到访时间默认为服务端保存时刻，新增访问登记和报修联系电话使用11位手机号。

巡检表单按宿舍、日期和轮次查询已有记录。已有同轮记录进入更正，随提交保留原时刻、图片和关联关系，可显式调整日期时刻或补图。上次巡检的四项分数可主动带入新记录。更正冲突会保留本地输入并要求对照新版本，作废继续在Web管理端办理。[Issue #6 业务说明](../docs/19-Issue6业务改进设计.md)

AI依赖后端配置的真实供应商。未配置、超限、超时或失败会显示可读原因并允许手动提交，不返回假建议；客户端不含模型密钥。

## 契约、资产与验证

`generate-models.py` 从 OpenAPI 1.3.0 的 114 个 schema 生成 114 个 ArkTS 模型，输出至 `entry/src/main/ets/models/ApiModels.ets`。接口变更后重新生成。枚举字段生成为 string，取值由共享契约与后端校验。[共享契约](../contracts/openapi.json)

中文展示字体来自已许可Noto Serif SC子集，内部family为Residence Editorial；为原生字体注册转为TTF，未修改版权及许可。`entry/src/main/resources/rawfile/OFL-Noto-Serif-SC.txt`保留OFL。庭院摄影署名在学生首页与「图片来源」页面可读，完整来源随包保存在`IMAGE-SOURCES.md`。照片不代表本平台服务学校的真实宿舍。

在项目根目录使用系统 Node 24 执行 `node --test harmony/tests/*.test.mjs`。2026-11-25 基线共 107 项通过，覆盖双主题对比度、路线变化通知及既有逻辑与恢复场景。纯计算检查时区、速度与计步边界；真实Api、图片草稿、工作会话Controller和系统适配器在替换原生I/O端口后验证迟到响应、订阅清理、资源释放、来源租约、批次边界与拒权降级。回放结果不代替模拟器交互或真机硬件测试。

目前只有API24模拟器：能核对系统页面入口、权限流程、安装运行和人工／回放场景。室内外定位精度、真实计步、熄屏持续、系统省电与耗电尚需真机；没有校园地图坐标时不生成虚构楼栋位置。默认通行时间继续采用基线，未校准步长不转换为精确速度。

ArkUI的`@Builder`默认按值传参，不能依赖替换后的State刷新旧参数。表单与记录片段使用单对象字面量`$$`按引用参数，上传区和工单详情直接读取当前State。记录列表键包含ID和版本，访客列表同时包含超时状态以反映没有修改记录时的状态变化。响应性仍须在设备验证。[华为@Builder说明](https://developer.huawei.com/consumer/en/doc/harmonyos-guides/arkts-builder/)

当前开发配置允许HTTP用于本机联调，发布环境应使用HTTPS。模拟器测试证据和业务验收结果统一记录在根目录交付文档，构建成功不能代替设备交互验证。
